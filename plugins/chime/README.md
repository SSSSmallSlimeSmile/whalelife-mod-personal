# chime · 提示音

一轮任务跑完、回复**真的发出去了**之后，在宿主机上响一声。

不是「模型开始说话就响」——它监听的是回复发出之后那个事件。所以长任务会有声音，快速问答不会。

## 装之前

- Windows（播放用的是 `SoundPlayer` / `WPF MediaPlayer`，别的系统跑不了）
- 不需要 Python、不需要网络
- 得有一个能出声的默认输出设备

**默认输出设备是空的，它就不响，而且不报错。** 这是这个插件最常踩的坑：命令退出码 0、日志有记录，就是没声音。先确认系统右下角那个喇叭能放出音来。

## 配置

```json
{
  "enabled": true,
  "sound_path": "",
  "wav_path": "",
  "min_seconds": 8,
  "cooldown_seconds": 3,
  "channels": [],
  "log": ""
}
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `sound_path` | 空 | **优先用它。** 可以是单个音频文件，也可以是目录——是目录时每次随机抽一个，不会连着放同一段 |
| `wav_path` | 空 | `sound_path` 没填时的回退，只能单个文件 |
| `min_seconds` | `8` | 这一轮耗时超过多少秒才响。设成 0 就是每轮都响 |
| `cooldown_seconds` | `3` | 两次响之间至少隔多少秒，防连响 |
| `channels` | `[]` | 空 = 所有通道都响；填了就只在这些通道响，比如 `["web"]` |
| `log` | 空 | 播放记录写哪个文件，空则不写 |

支持 wav（`SoundPlayer`）和 mp3（`WPF MediaPlayer`）。mp3 的时长是按文件头算的，VBR 的文件可能提前截断——建议用 wav。

## 页面

`/plugins/chime/`，所有字段都能在页面上改，底部有个「试听」按钮，点一下立刻放一次，用来确认设备通不通。

## 工具

`chime_test` —— 不给参数，立刻放一次。**不参与回合判定**，就是纯测试通道。

编长任务时想确认「到底会不会响」，用这个比自己等一轮快。

## 已知短板

- 音频通道依赖系统默认输出设备。设备一换（比如插耳机、HDMI 接管），可能就静音了，而它不会报错
- mp3 用 `MediaPlayer`，比 wav 那条路脆弱，能转 wav 就转
- 只在本人 Windows 机器上跑过，没有在第二台电脑验证过
