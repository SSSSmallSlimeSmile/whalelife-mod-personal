# peek · 看屏

按**画面变化**取帧的看屏插件。抓一段屏幕，只把真正变了的帧拼成一张图，交给识图模型说一遍。

和 `eyes` / `look_screen` 的分工：那个只看**当前一帧**；peek 抓**一段时间**，问「刚才发生了什么」「这个界面怎么变的」用它。

## 装

1. 整个 `peek/` 目录放进 `plugins/`。
2. 装依赖：
   ```
   pip install -r requirements.txt      # numpy + Pillow
   ```
   Windows 上不需要 pywin32：Win32 调用走 ctypes。
3. 识图模型，两级可以都配：
   - **对话模型（默认一级）**：什么都不用装。只要 WhaleLife 里有一个能看图的对话模型，就用它。
   - **本地 Ollama（默认二级）**：`ollama pull qwen3-vl:4b`，把 `ollama_model` 填成这个模型名。
     本地不起眼的好处是不花 API 的钱，坏处是要占显存、还得让 Ollama 一直开着。
   - **不备用**：`vision_backup` 设成 `none`，一级失败就直接报错。
4. **Python 解释器**。装出来的 `python` 不一定在 PATH 里（Windows 上可能只是商店的占位别名），三种指定方式，优先级从高到低：
   - 插件数据目录下的 `data/config.json` 里的 `"python"` 字段，填解释器的完整路径
     （是 `plugins/peek/data/config.json`，不是 `plugins/peek/config.json`——插件配置一律在 `data/` 下，放错地方会被当成没有配置，静默退回 `python`）
   - 环境变量 `WHALELIFE_PEEK_PYTHON`
   - PATH 里的 `python`
   前两个都不成立、`python` 又是占位别名时，工具会报错但说不出是解释器问题——先查这一项。

## 识图分两级

一级不行，自动换二级。配置页最上面两项：

| 字段 | 值 | 行为 |
|---|---|---|
| `vision_primary` | `chat`（默认） | 把图交给对话模型。不用装本地视觉模型，也不用 Ollama 在跑 |
| | 某个模型 id | 固定用这个。聊天用便宜的、看图用认得清的，可以分开 |
| | `ollama` | 交给本机 Ollama 里的视觉模型 |
| `vision_backup` | `ollama`（默认） | 一级报错、超时、或者那个模型不支持图片时，换它再试一次 |
| | `none` | 不备用，一级不行就直接报错 |
| | `chat` 或某个模型 id | 换另一个对话模型 |
| `ollama_model` | `qwen3-vl:4b` | 本地模型的名字，选 `ollama` 时用它 |
| `ollama` | `http://127.0.0.1:11434` | 地址，Ollama 装在别的机器上才要改 |
| `vram_guard` | `true`（默认） | 走本地 Ollama 之前先问一次还剩多少空闲显存；不够就不加载，直接说明原因。8GB 以下的显卡别关 |
| `need_vram_mb` | `5200` | 加载本地视觉模型至少要多少空闲显存（MiB）。`qwen3-vl:4b` 大约 4700–5200 |

`chat` 的意思是**跟随当前会话**：工具跑的时候拿这一次的人格，找它绑的模型。人格没单独指定模型时，用可用对话模型列表里的第一个。

两级填成同一个模型时只试一次，不会为同一个东西白等两遍。

**两级都不成才报错**，报错里带两边各自的原因。回复里那行「屏幕描述（…）」括号里是最后真正用上的谁；换过级的话后面多一行「说明：一级没成（…），换到二级 …」。

**二级留本地要留神显存。** 本机 8 GB 卡上 4B 视觉模型加载不进去，`vram_guard` 会当场拦住。拦住了说明另一条路也没接上，不是本插件的 bug。

旧配置兼容：以前是 `vision_mode` + `vision_model` 两个字段，读到会折成 `vision_primary`（`ollama` 原样保留，`chat` 带模型 id 就用那个 id），归一化之后不再写回。

## 和 eyes 同时开，显存会爆

`eyes` 是上游带的另一只看屏插件，只看当前一帧。它默认用 `qwen3-vl:4b`，而且是**写死在代码里的默认值**——`plugins/eyes/` 下没有 `data/config.json` 时，就没有任何地方能改它。

本机实测：两者同时开着，一台 8 GB 显存的笔记本在几秒内显存溢出，整机卡死，只剩语音进程还在跑。

**用 peek 就把 eyes 停掉。** 停用可以走插件管理，也可以把 `eyes` 加进 `config/plugins.json`：

```json
{ "version": 1, "disabled": ["watcher", "eyes"] }
```

本插件启动时会读一次那个文件：eyes 还在 `disabled` 外面，就往日志里写一条警告，配置页顶部也挂一条红字。停用之后这两处都会消失。

`vision_primary: "chat"`（默认）本身不碰本地显卡，但 eyes 不看你这条设置，它照样加载。所以「我切了对话模型，应该没事」是错的。
## 工具

`see_now`，参数：

| 参数 | 默认 | 范围 | 说明 |
|---|---|---|---|
| `seconds` | 10 | 2–60 | 抓多久 |
| `max_frames` | 6 | 1–12 | 一张图最多装几帧 |
| `max_width` | 1600 | 400–4096 | 成品图最大宽度 |
| `question` | 空 | — | 想重点看什么，可省略 |

返回：抓了几帧、留了几帧、耗时、成品图路径、边车备注、以及识图模型的描述。

## 想细看抓到的帧

`see_now` 交给模型的是拼图，缩过、拼过。想确认某一帧到底什么样，用 `comfy` 插件里的 `image_view`——给文件路径，它把原图送进上下文，刻度标的是原图像素。

本插件 `plugin.yaml` 里声明了 `optionalDepends: [comfy]`：装了才有这项能力，没装抓屏一切照常。

没有 `image_view` 时的坑：只能截屏看，拿到的是缩放后的屏幕坐标，和原图差一截。想按坐标去改某一块，就会偏。

## 取帧怎么算

- 每秒 6 帧，每帧压到 800×450 后算灰度差
- 灰度差过 10 才算「变了」，过 45 留 1 帧独占一格、过 18 留 2 帧、其余 3 帧挤一格
- 变化之间有过 0.4 秒不应期，避免一次切换被拆成一堆帧
- 整段没变化 → 一帧不留，复用上一张，并说明复用的是哪张

## focus：送整屏还是只送内容区

`config.json` 里 `"focus"`，三个值，默认 `auto`。

| 值 | 行为 |
|---|---|
| `whole` | 整屏照送 |
| `content` | 累计热点图挑「一直在变的那块」，占屏 6%–85% 才裁；低于 6% 算零散噪点，高于 85% 算整屏在动 |
| `auto` | **前台窗口优先**：先问哪个窗口有焦点，占屏 8%–92% 就用它；它里面若还有更贴画面的变化区，取交集。拿不到前台再退热点区（8%–60%）。都不成立整屏送 |

裁的时候，每帧按同一块区域裁，外壳（标签栏、地址栏、任务栏）一起去掉。裁完太小会放弃裁剪。

另外有一条只在 `whole` 下生效：整段只留下**一帧**且变化区不超过全屏 55% 时，直接从原图把变化区裁出来，细节比整屏清楚。

## 清晰度：格子多大、多清晰

一格里放一帧。格子越大，压进成品图后越清楚；但格子大了，一张图能装的帧数就少。

`config.json` 里两项，只管拼图，不影响抓帧：

| 字段 | 值 | 行为 |
|---|---|---|
| `tier_style` | `native`（默认） | 按每帧的变化分数自动定档：变化猛的给大格子独占，变化小的挤小格子 |
| | `up` | 在自动结果上整体往清晰偏一档 |
| | `down` | 整体往省偏一档，能多装帧 |
| `tier_lock` | `0`（默认） | 不锁，交给 `tier_style` |
| | `1`–`3` | 强制锁死这一档，`tier_style` 不再起作用 |

三档的格子：1 档独占整行，2 档一行两个，3 档一行三个。档越小越清楚，能装的帧也越少——锁 1 档一张图最多 3 帧，锁 3 档能到 12 帧。

**锁档会压掉 `max_frames`**：`see_now` 传 12、但配置锁了 1 档，实际只装 3 帧。

想看清屏幕上的字，填 `tier_lock: 1`；想看整段时间里画面怎么变，填 3。

工具回复里会带一行「档位：…」，说明这一轮用了哪几档、各几帧，方便判断是节奏还是锁档导致的。

## 已验证 / 未验证

已验证（本机实跑）：

- 边车单独跑：抓帧、判分、留帧、装箱、落盘，退出码 0
- `numpy 2.2.6` / `Pillow 10.4.0` 下 `py_compile` 通过
- `focus=whole` 与 `content` 两条分支的备注措辞来自实际输出
- 插件在 WhaleLife 里加载、`see_now` 注册成功、识图返回正常
- 旧版固定走本地 Ollama 的识图，实跑出过描述

未验证：

- **两级链的代码只做了单元测试**：十种配置组合（重复、`none`、不存在的 id、按模型名、大小写）都按预期解开，但没在运行中的进程里跑过真识图
- **真失败换二级没撞到过**：`describe` 的兜底写了，实际没构造出「一级挂了换二级」的现场
- 对话模型看图的实际效果没和本地 qwen3-vl 对比过，认字谁强不知道
- `pip install -r requirements.txt` 没在干净的机器上跑过——依赖是按已装好的环境写的
- 「前台窗口铺满整屏就不裁」这种情形没构造出来过，没测
- `auto` 的前台优先只在 Windows 上有效（走 ctypes 调 user32/dwmapi）；非 Windows 直接退热点区
- `tier_style` / `tier_lock` 没在改配置后实跑对比过，格子大小的效果是按代码算的

## 已知取舍

- 屏幕分辨率取决于屏幕本身，抓屏不缩放；成品图才按 `max_width` 压
- `focus=content` 的阈值（2.5）比整屏那套低，静止画面里光标闪一下、时钟跳秒也可能留一帧，数量由 `max_frames` 兜住
- 每帧拼成 800×450 的格子，画面文字到模那儿基本糊，别指望它读小字
- 走对话模型时，一张拼图 base64 后可能上百 KB，会按输入 token 计费；觉得贵就把 `max_width` 调小，或切回本地
